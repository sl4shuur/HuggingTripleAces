# Shared soil CV package

Status: version 0.1.1 is implemented in `soilcv/`. See `soilcv/README.md` for the working API and examples. The later diagnostics, ensembles, and method-specific SSL helpers remain future work.

Goal: use the same data, folds, scoring, and run files for CNN, ViT, frozen features, SSL, and ensembles. Train on Kaggle. Keep the source code in this repo.

## Files and releases

Repo source: `advanced-cv/lab-1/soilcv/`. Packaging config: `advanced-cv/lab-1/pyproject.toml`.
Python import name: `soilcv`.
Kaggle code dataset name: `soil-cv-utils`.

A code dataset release contains:

```text
soilcv/
    __init__.py
    config.py
    data.py
    tiles.py
    curves.py
    metrics.py
    nn.py
    training.py
    features.py
    tracking.py
    artifacts.py
    assets/
        sample_folds.csv
    README.md
release.json  # generated by package_soilcv.py
```

`__init__.py` exposes the package version. Importing the package does not log in, read secrets, install packages, or start a run. NumPy metrics do not need to import PyTorch or W&B.

Keep three resources apart:

- Code dataset: Python files, the fixed sample folds, release info, and a small import example.
- Cache dataset: tiles, photo and tile manifests, source hashes, and the crop settings. Keep the current 64 mm / 224 px cache as a separate named setting.
- Run outputs: weights, features, OOF curves, reports, and submissions. Save these in notebook output and W&B. Large reusable outputs may later get their own dataset or model resource.

The competition images and labels stay in the original competition input. Do not copy the full EDA or original image set into a code release.

Pin the code and cache dataset versions in each experiment notebook. Record package version, source commit or source hash, input versions, folds hash, cache hash, and library versions in every run. A code update does not update old notebooks by itself.

## Shared modules

| Module | Public API | Purpose |
| --- | --- | --- |
| `config.py` | `ExperimentConfig`, `load_config`, `save_config`, `seed_everything`, `seed_worker` | One saved config for a full experiment. Set seeds for Python, NumPy, PyTorch, and data workers. |
| `data.py` | `load_metadata`, `load_folds`, `validate_folds`, `TileDataset`, `sample_weights` | Read IDs, labels, cameras, and scale estimates. Load the fixed folds. Return IDs with every tile. Balance sample/photo/tile weights. |
| `tiles.py` | `estimate_ppm`, `make_tile_manifest`, `build_tile_cache`, `check_cache` | Use EXIF orientation and a crop size in mm. Save exact crop boxes, source PPM, estimated output PPM, and cache settings. |
| `curves.py` | `TARGET_COLUMNS`, `SIEVE_MM`, `validate_curves`, `repair_curves`, `aggregate_features`, `aggregate_predictions`, `make_submission` | Keep target order and units fixed. Average tiles to photos, then photos to samples. Check the final curves and submission IDs. |
| `metrics.py` | `emd_per_sample`, `evaluate_samples`, `grain_size`, `range_errors`, `group_errors`, `summarize_cv` | Official EMD, MAE, worst-point error, D10/D50/D60 error with valid-pair counts, and errors by range, group, and device. |
| `nn.py` | `MassCurveHead`, `EMDLoss`, `set_trainable`, `freeze_bn_stats`, `make_param_groups` | A valid regression output and the differentiable score. Reuse parameter freezing and explicit learning-rate/weight-decay groups. |
| `training.py` | `train_one_epoch`, `predict_tiles`, `validate_epoch`, `fit_supervised_fold` | Shared supervised loop for CNN, ViT, linear probe, and fine-tuning. Support CPU/GPU, AMP, accumulation, clipping, early stop, and scheduler steps. |
| `features.py` | `extract_features`, `save_features`, `load_features` | Cache frozen features with ordered IDs and an exact encoder/preprocessing identity. Use the same feature files for Ridge, k-NN, and probes when valid. |
| `tracking.py` | `start_run`, `log_epoch`, `log_evaluation`, `log_artifact`, `finish_run` | Online W&B with a Kaggle Secret. Use the same names for all model families. |
| `artifacts.py` | `save_checkpoint`, `load_checkpoint`, `save_predictions`, `save_environment`, `ComputeMeter` | Save resumable state, sample-level predictions, source/runtime info, elapsed time, and memory use. |

Version 0.1.0 uses functions and these few small classes. Experiment config can be a dataclass plus JSON. Add a class only when it holds state or implements a PyTorch dataset/module.

Model constructors and model-specific recipes live with each modelling part. An encoder adapter returns one feature vector per image. It must define its pooling and preprocessing; the package must not guess these from an output tensor.

## Contracts that all parts share

1. Targets are 11 cumulative percentages in the official column order, in the range 0 to 100.
2. The official EMD uses the first 10 point errors and the 10 log10 interval widths. Keep its units unchanged. A training loss scale must be a named config value.
3. `MassCurveHead` maps 11 logits to 11 non-negative mass bins with softmax, then takes a cumulative sum times 100. The first bin is below the first sieve. The other bins cover the next intervals.
4. For an unconstrained Ridge or PCA output, curve repair is an explicit saved choice. Use the same repair in validation and test. Do not repair inside the official metric without telling the caller.
5. Each prediction carries its sample ID. Tile predictions also carry photo and tile IDs. Join by IDs, not row position.
6. Validation produces exactly one OOF curve for every labelled sample, from a model that did not train on that sample. Reject missing, repeated, or extra sample IDs.
7. A photo gets the mean of its tile curves. A sample gets the mean of its photo curves. A photo with more tiles must not get more weight by accident.
8. Frozen-feature models may average features before fitting the regressor. Save this choice as `aggregation=feature_mean`; it differs from averaging output curves.
9. Keep the original four folds from EDA. Extra split studies are diagnostics. Do not regenerate the main folds in each notebook.
10. Report sample-mean EMD, fold mean/std, and group results. Save both mean and median image-free baselines as references.

Device reports need a separate definition: aggregate held-out photo predictions to one curve per sample and device. One sample may be in two device reports. Report the sample counts; do not combine device groups as if they were disjoint.

Select the best checkpoint by sample-level validation EMD. Keep tile loss separate. Mark a CV summary as complete only when all expected fold predictions are present.

The sampler should give each physical sample the intended training weight. A flat list of all tiles otherwise gives samples with many photos more influence. Tile labels are sample-level labels; one tile may not show the full soil mix.

## Scale, transforms, and caches

Keep `ppm_est` and the method used to estimate it. Preserve the note that absolute PPM is not verified. A new cache must not turn this estimate into a claimed measurement.

Tile cache identity includes source image hashes, orientation handling, scale method, crop size in mm, output pixels, crop positions, and interpolation. A changed setting gives a new cache identity. Save relative file paths so the cache can move to a different Kaggle mount.

Store the actual output PPM after integer crop rounding. Native crops have no resize but may have different pixel sizes across cameras.

Use fixed physical crops before model input resize. Start with rotations by 90 degrees, flips, and small light/colour changes. A random resized crop must not silently change physical field of view. ViT, CNN, and SSL recipes can choose different transforms, but must record them.

Feature cache identity also includes model name, exact pretrained weights/revision, encoder state hash, pooling, image normalization, and tile cache identity. A tuned encoder needs a new cache. Fold-trained encoders need fold-specific identities.

A fixed public encoder can extract deterministic features for all photos once. Fit scaler, PCA, Ridge, k-NN choices, and other learned transforms on train samples inside each fold. Fit domain SSL on that fold's train photos for the standard validation protocol.

## W&B online

Default W&B entity: `public-team`. Default project: `soil-grain-size`. Both can be changed in `ExperimentConfig`.

Secret label: `WANDB_API_KEY`. Attach it to each Kaggle notebook that starts a run. Enable Internet for online logging.

`start_run` gets the key from `UserSecretsClient().get_secret("WANDB_API_KEY")`, calls W&B login, then starts an online run. The key is not part of `ExperimentConfig`, saved config, logs, or dataset files. If login or run creation fails, show the error before a long training run. Do not silently change to offline mode.

Use one W&B project for the lab. One experiment has one group ID. Each fold has its own run. A separate summary run records the combined OOF score and fold mean/std. Reusing a run ID is for resuming that same run, not a new experiment.

Common fields:

- Config: experiment ID, hypothesis ID, stage, model, exact weights, seed, fold, input/code/cache versions, transforms, loss, optimizer, schedule, training scope, and aggregation.
- Train log: loss, learning rate for each parameter group, epoch, and step. Do not call tile loss a sample-level EMD score.
- Validation log: sample-level EMD, diagnostics, group counts/errors, and the chosen checkpoint.
- Compute log: device, elapsed time by stage, GPU-hours, peak GPU memory, and CPU memory when available. Keep W&B system logs too.
- Artifacts: config, environment, OOF predictions, checkpoints, per-sample errors, plots, and final submission when one is made.

Save files in `/kaggle/working/runs/<experiment_id>/fold_<n>/` as well as logging to W&B. Kaggle input folders are read-only. Package code and cache readers must not write into them.

A resume checkpoint contains model, optimizer, scheduler, AMP scaler, epoch, global step, random states, run ID, and config/data identities. W&B run resume alone does not restore training state. For Ridge or PCA, save the fitted pipeline and its metadata together.

## Shared training, different methods

A frozen encoder must use evaluation mode for feature extraction. Freezing gradients alone does not freeze BatchNorm running statistics. Keep the BN policy explicit and apply it after calling `model.train()` when needed.

Use the same supervised loop for curve regression from CNN, ViT, or an SSL encoder. The model and optimizer recipe are inputs to that loop.

SSL pretraining has a separate loop and loss for each method. Reuse data, transforms, seeds, logging, checkpoints, compute tracking, and later curve evaluation. Do not force DINO teacher/EMA logic or MAE reconstruction into the regression loop.

Use PyTorch's existing L1 and SmoothL1 losses when testing them. Add a custom loss only for a task-specific calculation such as EMD.

## Add when the part needs it

- `diagnostics.py`: common sample selection, curve/photo plots, range/group reports, scale tests, CKA, and camera/shortcut controls. Grad-CAM and attention extraction keep small model-specific adapters.
- `ensemble.py`: align OOF files by sample ID, check matching folds/protocols, compare error correlations, and blend curves. Report tuned blend CV honestly; fitting weights on all OOF labels and scoring those same labels is optimistic.
- A sample-bag dataset if we train directly on sets of photos/tiles. It uses the same manifests and validation code.
- LoRA and model-specific SSL helpers when their first experiment is added.

Do not publish every future method in the first release. Fix the common contracts now; extend the implementation as real experiments need it.

## First release and checks

Build the data/fold/curve/metric functions, EMD loss and curve head, artifacts, and W&B setup first. Then add frozen-feature extraction and the small supervised loop with the first image baselines. The same release can serve later CNN, ViT, and SSL fine-tuning.

Use Kaggle's tested PyTorch/CUDA setup as the starting point. Record versions and make dependency changes explicit. Do not upgrade GPU libraries as an import side effect.

Small CPU checks before publishing:

- NumPy EMD matches known cases and the PyTorch loss. Test zero error, log weights, target units, and the last-point rule. Check finite gradients.
- The curve head and explicit repair give valid shapes, order, range, and endpoint.
- Folds have no sample overlap. OOF and submission IDs are complete and unique.
- Aggregation gives equal photo/sample weight even with unequal tile counts.
- Changed cache settings or encoder state reject an old cache identity.
- Saving/loading a tiny checkpoint restores state. One small CPU fit/predict run works.

After the secret is added, do one small online W&B smoke run on Kaggle. Check its config, one metric, one artifact, and final run status. Do not start long training before this works.
